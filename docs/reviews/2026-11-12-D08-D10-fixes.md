## 二、规划输入与权限

`source=model` 需要 Run 的规划 provider、用途为 planning 的模型授权以及 `grantId`、`idempotencyKey`。ModelGateway 继续执行 provider、授权范围、预算和发送清单检查。

默认只发送明确标注的元数据。需要发送选定上传文件的正文时，API 传 `includeInputContent=true`；CLI 增加 `--include-input-content`，并可用 `--max-input-bytes` 设置总正文上限。默认 65,536 字节，上限 131,072 字节。

正文读取同时要求文件属于当前项目、在 Run 选定输入中且被模型 grant 允许；路径位于平台输入存储内，文件 SHA-256 与上传记录一致，内容可按 UTF-8 解码。二进制和过大文件会阻塞，需后续注册有审计记录的提取/摘要流程。不会自动扫描原始仓库内容。

CapabilityCheck 现在要求 `config:<profile.config_hash>` 证据引用。历史能力证据没有绑定当前配置时需要重新验证，不能直接视为受信能力。

## 三、内部身份与控制队列

- 新增 `AGENTFORGE_INTERNAL_SIGNING_KEY`，通过安全配置提供独立随机密钥，至少 32 字符。示例配置只含占位说明，没有向真实 `.env` 写入密钥。
- 签名票据绑定 subject、audience、request 和过期时间。Agent 仅接收必要的短期票据，不接收平台用户 bearer 或签名密钥。无公开密钥签发接口。
- 审核提交要求 `X-Agent-Ticket`，并绑定对应 review request。普通用户的 `X-Reviewer-Instance-Id`、任意 `X-Internal-Service` 不能声明受信审核身份。
- 新协作任务使用 `agentforge-control`。运行入口为 `agentforge queue work --control`，启动时检查迁移和业务连接的 PostgreSQL `current_user = agentforge_driver`；任务入口也复核角色。
- 控制进程的 `AGENTFORGE_DATABASE_URL` 需用已授权的 driver 角色，队列连接通过 `AGENTFORGE_QUEUE_DATABASE_URL` 配置。普通 queue worker 继续使用原队列，不应获得控制进程的业务连接和签名密钥。
- 原生发送和停止使用 AUTOCOMMIT 连接上的实例级 advisory lock。该锁不持有业务事务；竞争方安全重试，崩溃后未知结果不会被重新发送。
